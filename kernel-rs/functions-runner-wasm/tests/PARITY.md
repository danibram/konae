# StarlingMonkey parity tests

Use the [runtime contract](../../../docs/architecture/functions-wasm-runtime-contract.md) for author behavior, diagnostic bounds and measurements. Compare the IPC/2 spike at `76d98e32` with a matched IPC/3 Kernel and runner at `0e3bf8e9`. Test production with the IPC/3 StarlingMonkey runner and Kernel from the same build. A mixed pair only verifies ABI mismatch handling.

The test names below identify cases to add or extend. The expected column gives the production result. A case can continue to fail on the frozen spike.

## Run the tests

Run the two runner crate suites with `--test-threads=1`, the full `cargo test -p kernel -p konae` suite and the full ignored Kernel suite with `KONAE_TEST_FUNCTION_WORKER` pointing at the matching StarlingMonkey launcher. Use a cache-only launcher to keep initialization time outside request deadlines. Prepare the fixtures first. Run the full Bun suite and editor build. If the executor changed, run the Linux musl check with `--tests`.

Use the existing 200-case fixtures under `spikes/functions-runtime/checks`. On the IPC/3 worker, use the [spike suite driver](../measure/suite.py) as the starting point. Update its private IPC driver for the named-bundle Init and Invoke, then verify all expected results and report the skips. The historical `checks/run_all.py` driver expects an HTTP lab server. The bare worker cannot replace its binary. Run the [Hono fixtures](../measure/hono.js) through IPC/3 and through a real Kernel to check header filtering.

For the real artifact, build and export an app with a function and a named action. Run a matching Kernel with `KONAE_FUNCTIONS_RUNNER` and `KONAE_FUNCTIONS_DEVELOPMENT=1`. Call the same function twice, then repeat on a second installation from the exported folder. Show the HTTP status and response, a durable row mutation and the same app user signing in after export/import. Include the 100 MB boundary requests, a multipart byte round trip and an owner read-back of one exception. Keep the response RSS measurements separate from correctness assertions.
