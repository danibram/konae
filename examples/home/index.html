Open source app builder

Describe an app. Publish it. Take it with you.

Konae turns a description into a working web app with its own database, sign-in, files and address. An assistant writes it, or you write the code yourself. Any app can leave for another server with its accounts and its data.

For things like a club's sign-up sheet, a shop's stock list or a team's room booking.

Every app comes with its backend

You set up no server, no database and no login page. An app has these from its first publish, and you ask for each one in a sentence or declare it in a file.

Every piece, and when to use it

  • A database

    Its own SQLite database, up to 256 MiB. The tables live in one file, schema.sql.

  • Accounts and sign-in

    Email and password, with Google as an option. You choose who may sign up, from anyone to invited people or a list of emails.

  • Its own address

    A hostname the moment it publishes. You can add your own domain, or a short path on this site.

  • File uploads

    Public or private files, 2 MiB each unless whoever runs the server raises it.

  • Email when a row changes

    A new booking can email you, or the person who made it. The address never comes from what a visitor typed.

  • Scheduled work

    A task runs on a timer, every 5 minutes to every 24 hours, or once a day at a set time.

  • Webhooks in, calls out

    Other services call the app with a signature or an API key. The app calls them from the server, so no secret reaches the browser.

  • Rules about who sees what

    Each read and write names who may run it. That can be any visitor, a signed-in person, or a role your app keeps.

Describe it, or write it. Same files.

The assistant writes the files you would write yourself. You can switch between asking and editing at any point, and both make one app at one address.

What the editor accepts, the server runs

The editor checks an app before it runs, and the server checks it again with the same sentence wherever the app goes. Try one of those rules here. A list has to name how many rows it reads, so it cannot grow without bound as the table grows.

How the two checks stay the same

The box runs the editor's own row-limit check, from the same source file.

Your app is a folder you can take

An export writes one folder with the app's pages, database, accounts and files. Import it on another server running Konae, or run it alone with Docker. People keep their passwords and every row is where it was. A few things stay behind on purpose.

For developers

The source is on GitHub under the MIT licence. Commands run from a checkout of the repository with Bun. The local server in dev also needs Rust.

Run your own installation

The editor, the server and storage in one stack. The editor opens at app.localhost:8080, and the first owner signs up with the installation's setup key. On the local stack the setup key is local-development-key. Set your own with KONAE_ADMIN_KEY before anyone else can reach the server. One app can also leave on its own as a folder that runs with Docker.

Make your first app

Three steps, and the first two you do once.

  1. 1

    Get an invitation code

    Ask the person who sent you this link, or whoever runs this site. You use it once, to create your account. Without one you can still read the docs or run your own installation.
  2. 2

    Get an AI key

    The assistant runs on your own account with Anthropic, OpenAI or OpenRouter, which bills you for what it uses. Paste the key in the editor's settings. It stays in your browser.
  3. 3

    Describe the app, then publish it

    Say what it is for and who uses it. Ask for changes the same way. It gets its own address, and you decide who may open it.
