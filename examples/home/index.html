Make a small app. Take it with you.

Describe a small app and an assistant builds it, or write the code yourself. Either way the same checks apply, such as every list naming how many rows it shows, and the app can move to another server with its accounts, its data and its rules.

For things like a club's sign-up sheet, a shop's stock list or a team's room booking.

You need an invitation code and an AI key. How to start

  1. 1

    Get an invitation code

    Ask the person who sent you this link, or whoever runs this site. You use it once, to create your account. Without one you can still read the docs or run your own installation.
  2. 2

    Get an AI key

    The assistant runs on your own account with Anthropic, OpenAI or OpenRouter, which bills you for what it uses. Paste the key in the editor's settings. It stays in your browser.
  3. 3

    Describe the app, then publish it

    Say what it is for and who uses it. Ask for changes the same way. It gets its own address, and you decide who may open it.

Describe it, or write it. Same files.

The assistant writes the files you would write yourself. You can switch between asking and editing at any point, and both make one app at one address.

Describe it

YouA page for Saturday football with fourteen places, where anyone with the link can see who is in.

AssistantAdded a list of players that shows at most 14 rows.

Write it

One rule, word for word, in the editor and on the server

A list has to name how many rows it reads, so it cannot grow without bound as the table grows. The editor checks that before the app runs, and the server checks it again with the same sentence wherever the app goes.

How the two checks stay the same

The box runs the editor's own row-limit check, from the same source file.

What travels, and what you set again

A package carries the app to another server running Konae. There it answers with the same accounts, the same rows and the same rules about who may open it and who may read a row. A few things stay behind on purpose.

How a package moves an app

You set again on the other server

  • The Google sign-in client
  • Signing secrets
  • New API keys

People sign in again there with the same password, or with Google once you set its client.

For developers

The source is on GitHub under the MIT licence. Commands run from a checkout of the repository with Bun. The local server in dev also needs Rust.

Run your own installation

The editor, the server and storage in one stack. The editor opens at app.localhost:8080, and the first owner signs up with the installation's setup key. On the local stack the setup key is local-development-key. Set your own with KONAE_ADMIN_KEY before anyone else can reach the server. One app can also leave on its own as a kit that runs with Docker.
