In every app

Accounts, data and email are already there.

You set up no server and build no login page. An app has all of this from its first publish.

  • Email when something changes

    A new booking can email you, or the person who booked.

  • Its own address

    A web address when it publishes. Add your own domain later.

  • Work on a timer

    A task runs every few minutes, or once a day at a set time.

  • Links to other tools

Keep it yours

Your app is a folder. Take it anywhere.

Konae saves the whole app as one folder, with its pages, its members and everything they saved. Open that folder on another Konae server, or run it alone with Docker, and nobody signs up again.

One app, two ways in

Ask in plain words. Or open the files.

The assistant writes the same files a developer would. Someone who does not code and someone who does can work on one app, and switch at any point.

For developers

Plain files, SQLite, no lock-in.

The editor is TypeScript and the server that runs apps is Rust, both on GitHub under the MIT licence. An app is its pages, schema.sql, the reads and writes in actions.json, and a SQLite database.

Edit the files on your machine

Sign the CLI in through the browser, make the app's folder, run it on a local server and publish it here. Commands run from a checkout with Bun, and the local server also needs Rust. The folder is plain files you can keep in Git.

The CLI guide

Connect an agent

An MCP client builds, checks and publishes with the same rules as the editor. Start with the platform_guide tool.

The reference llms.txt

Run your own installation

The editor, the server and storage in one stack. The editor opens at app.localhost:8080, and the first owner signs up with the installation's setup key. On the local stack that key is local-development-key. Set your own with KONAE_SETUP_KEY before anyone else can reach the server.

Operate an installation

The same rules on every server

The editor checks an app before it goes live. Every server that runs it checks again and refuses the same mistakes with the same words, so an app the editor accepts keeps working after it moves. Try one rule. A read has to name how many rows it returns, so it stays fast as the table grows.

Questions

Before you ask for an invitation.

Do I need to know how to code?

No. You describe the app and ask for changes in plain words. The app is still made of ordinary files, so someone who codes can open them and keep working on the same app.

What kind of app is it for?

Small apps for a group: a sign-up sheet, a room booking, a stock list, a members' area. Each app has its own database, its own accounts and its own address.

What does the assistant cost?

The assistant runs on your own key from Anthropic, OpenAI or OpenRouter, and that provider bills you for what it uses. You paste the key in the editor and it stays in your browser. This site does not provide a key or resell model calls.

How do I get in?

Request an invitation with your email. The people who run this site send you a code, and you use it once to create your account. You can also run your own installation, where you decide who gets in.

What happens to my app if I leave this site?

You export it as one folder and open it on another Konae server, or run it alone with Docker. Members keep their passwords and every record is where it was. You set up Google sign-in and the keys of connected services again.

Is it really open source?

Yes. The editor and the server are on GitHub under the MIT licence, and one docker compose up starts your own installation.
