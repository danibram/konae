The Capsule

A Capsule is the editable source of one Project, taken as one unit. The editor, the agent and the CLI all read and write this shape.

Layout

mini-app/
├── index.html
├── about.html        # every .html at the root is a page
├── 404.html          # answers an unknown path under the default routing
├── pages/            # more pages, published without the prefix
├── public/           # published as they are
├── styles.css
├── app.js            # or src/main.ts
├── src/
│   └── feature.ts
├── schema.ts
└── actions.json

This is the layout of docs/architecture.md. An app that publishes with littlebox also carries schema.sql, as the apps in examples/ do, and an External Project keeps its manifest in littlebox.json.

What each file does

FileRole
app.js or src/main.tsThe entrypoint. Relative imports from it are bundled. Today a Capsule imports only its own files.
index.html, other .htmlPages. Every .html at the root and under pages/ is a page. Pages under pages/ publish without the prefix.
styles.cssStyles the pages load.
schema.tsThe Database Model, from which schema revisions and migrations are derived.
schema.sqlThe schema the Kernel and the Gate parse for publication. It may only create tables and indexes, and it must be safe to run twice.
actions.jsonThe Server Action declarations. See Server Actions.
404.htmlThe page answered for a path the Deployment does not hold, under the default routing mode.
public/Files published as they are.

The sources do not agree on which file holds the schema. CONTEXT.md and docs/architecture.md name schema.ts as the Database Model. kernel-rs/src/guide.rs says to declare the schema in schema.sql for artifact publication, and docs/architecture.md says the Kernel parses actions.json and schema.sql at release_plan. The examples carry both files. Treat schema.sql as the one the Kernel reads at release.

From Capsule to Build Artifact

A Deployment serves the Build Artifact built from the Capsule, not the Capsule. Every builder makes it by one rule set.

  • Each page gets the SDK injected.
  • The files the pages load, and public/, are included.
  • Binary files travel as base64, named in encodings.
  • A build that names a file the Capsule does not hold is refused.

The routing mode is pages by default. A path the artifact does not hold answers 404 with its 404.html. In spa mode such a path serves index.html. The builders and the Kernel refuse any other mode with the same words.

The Gate checks the schema and actions.json. A page that names a missing file passes the Gate and fails at build or release. See Named divergences.

What the published page may do

A published app runs under the Kernel's Content Security Policy. Its own inline scripts and same-origin files load. Inline event handler attributes such as onclick="..." and other origins do not. Attach listeners in JavaScript and keep scripts and fetches on the app's own origin. The editor preview applies no such policy, so code that works there can still fail once published.

Who holds the source

A Managed Project keeps its source in Littlebox, and changes pass through the editor and the Validation Gate. An External Project keeps its source in the owner's folder. littlebox init creates an External Project. Eject turns a Managed Project into one, and the step cannot be undone.
