CLI

The littlebox command makes an app in a folder, runs it on a Development Kernel, publishes it, and moves it. Run it from the repository root with Bun.

bun run littlebox -- <command> [options]
bun run littlebox -- help

Every command except login reads its credential from <folder>/.littlebox/credentials.json or from LITTLEBOX_MCP_TOKEN. Never put a token in app source.

login

bun run littlebox -- login --dir ./my-app --url http://localhost:4173 [--manage-users] [--export-data] [--manage-lifecycle] [--verify-from <mailbox.jsonl>]

Reads LITTLEBOX_EMAIL and LITTLEBOX_PASSWORD. Add LITTLEBOX_INVITATION_CODE, the code the operator issued, to create the account, or LITTLEBOX_SETUP_KEY for an installation's first owner. It saves a 24-hour token with read, write and publish.

FlagAddsFor
--manage-usersmanage_usersInviting app users, suspending, changing the Signup Policy
--export-dataexport_dataExporting live data
--manage-lifecyclemanage_lifecycleEject and migration

A delegated token cannot widen itself later, so the flags are the only way the CLI gets these permissions. On a Kernel that verifies email, creating the account sends a link. --verify-from reads that link from a development mailbox on this machine and works only with a Kernel on localhost or 127.0.0.1.

init

bun run littlebox -- init --dir ./my-app --name 'My app' --url http://localhost:4173

Registers a project and writes a template into an empty folder. The project is External.

dev

bun run littlebox -- dev --dir ./my-app [--port 8796]

Compiles and starts the Rust Kernel with data under .littlebox/dev-data, with its own identities and no link to production. It publishes the build there, sets the signup policy to Open so test accounts can sign up, and rebuilds when the sources change. Its email, notices included, goes to .littlebox/dev-data/mailbox.jsonl. When the command exits, the Kernel stops and the data stays in the folder.

build

bun run littlebox -- build --dir ./my-app

Writes .littlebox/artifact.json.

contract

bun run littlebox -- contract --dir ./my-app [--out <folder>]

Writes action-contract.json, its schema and action-contract.md, from actions.json and schema.sql.

publish

bun run littlebox -- publish --dir ./my-app

Builds and publishes. Set each signing secret with secret_set first, because a release that signs with an unset secret is refused. On a first release it sends project.manifest.signupPolicy from littlebox.json.

conform

bun run littlebox -- conform --url <app URL> --contract ./my-app/action-contract.json [--token <app session>] [--key <API key>] [--secret <name>=<value>] [--inputs <file>]

Calls every action and checks the answers against the contract. It runs each mutation once, so point it at a test Deployment.

export

bun run littlebox -- export --dir ./my-app [--out <file>] [--with-data]

Writes a self-hosted kit. --with-data adds the live package and needs a credential from login --export-data.

eject

bun run littlebox -- eject --dir ./empty-folder --project <id> --url <Kernel URL> [--revision <n>]

Moves a Managed project's sources into the folder. Needs login --manage-lifecycle.

domain

bun run littlebox -- domain --deployment <id> [--set <hostname> | --clear] [--url <Kernel URL>]

Shows, sets or clears the app's custom domain. --set prints the TXT record that proves you control the hostname. Run it again once the record is at your DNS provider.
