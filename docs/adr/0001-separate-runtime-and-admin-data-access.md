# Separate runtime and administrative data access

Littlebox deployments will never expose a SQLite file, database credential, unrestricted SQL-over-HTTP endpoint or export capability to browser code. Deployed apps access protected data only through named server actions evaluated by the Littlebox Kernel using the deployment, actor and grants; the editor uses the Kernel's separate owner-authenticated Admin Interface for SQL Studio, migrations, backups and export. Deployment visibility controls access to the application shell independently from data authorization, so a public app can still hold private data and a private app still applies per-actor data rules. This separation costs more platform work than shipping SQL credentials or a generic query endpoint, but it is required because anything delivered to a browser can be extracted or replayed.

This boundary prevents downloading or querying the database outside declared actions; it cannot make data already returned to an authorized browser uncopyable. Client JavaScript is also inspectable by anyone allowed to open the deployment, including private deployments, so sensitive logic and secrets must remain in server actions.
